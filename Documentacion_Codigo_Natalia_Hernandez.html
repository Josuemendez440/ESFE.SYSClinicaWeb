1. Investigación Previa de Estándares de Documentación

En el ciclo de vida del software, el código fuente es el artefacto central sobre el cual interactúan múltiples desarrolladores. Cada lenguaje de programación formaliza su propio estándar para estructurar la documentación técnica:

  • Java: Utiliza el estándar Javadoc (/** ... */) con anotaciones como @param, @return y @author.
  • C# (.NET): Utiliza el estándar de Comentarios de Documentación XML precedidos por triple barra diagonal (///), formalizado en la especificación ECMA-334.
  • Python: Aplica Docstrings mediante triples comillas (""" ... """) bajo la directiva PEP 257.
  • JavaScript / TypeScript: Utiliza JSDoc con descriptores de tipo e interfaz.

2. Estrategia de Documentación en ESFE.SYSClinicaWeb

Para este proyecto, desarrollado en C# y ASP.NET Core, se estableció una estrategia basada en el estándar XML nativo de Microsoft Roslyn. Esta elección responde a tres necesidades críticas:

Importancia para el Mantenimiento y Comunicación del Equipo:

1. Soporte en tiempo real mediante IntelliSense: En Visual Studio y Visual Studio Code, el motor Roslyn analiza los bloques /// al instante. Cualquier desarrollador que instancie una clase o invoque un método visualiza inmediatamente una ventana emergente (tooltip) con el resumen, parámetros y reglas de negocio sin interrumpir su flujo de trabajo.

2. Claridad en Reglas de Negocio Complejas: Campos sensibles de la clínica (por ejemplo, el cálculo del anticipo del 25%, el saldo pendiente del 75%, o el correlativo de expedientes PAC-0001) quedan claramente descritos para evitar ambigüedades lógicas entre desarrolladores front-end y back-end.

3. Generación Automatizada de Metadatos XML: Habilitando la propiedad <GenerateDocumentationFile>true</GenerateDocumentationFile> en el archivo de proyecto .csproj, el compilador genera un archivo XML que alimenta directamente portales técnicos, generadores tipo Swagger/OpenAPI o DocFX.

namespace ESFE.ClinicaWEB.Models
{
    /// <summary>
    /// Representa el modelo de vista (ViewModel) para la gestión y registro de citas médicas en el sistema clínico.
    /// Contiene la información del paciente, médico asignado, fecha, horarios y control de pagos/anticipos.
    /// </summary>
    /// <remarks>
    /// Autor: Natalia Elizabeth Hernandez
    /// Versión: 1.0
    /// Fecha: Septiembre 2026
    /// </remarks>
    public class CitasViewModel
    {
        /// <summary>
        /// Identificador único autoincremental de la cita médica.
        /// </summary>
        public int Id { get; set; }

        /// <summary>
        /// Nombre completo del paciente que solicita y asiste a la consulta médica.
        /// </summary>
        [Required(ErrorMessage = "El nombre del paciente es obligatorio")]
        public string Paciente { get; set; } = string.Empty;

        /// <summary>
        /// Especialidad médica requerida para la consulta (ej. Medicina General, Odontología).
        /// </summary>
        [Required(ErrorMessage = "La especialidad es obligatoria")]
        public string Especialidad { get; set; } = string.Empty;

        /// <summary>
        /// Monto monetario total fijado para la consulta o servicio médico brindado.
        /// </summary>
        public decimal PrecioTotal { get; set; } = 50.00m;

        /// <summary>
        /// Monto abonado previamente por el paciente en concepto de anticipo o reserva de cita (25%).
        /// </summary>
        public decimal MontoAnticipo { get; set; } = 12.50m;

        /// <summary>
        /// Monto restante que el paciente tiene pendiente de cancelar el día de la cita (75%).
        /// </summary>
        public decimal SaldoPendiente { get; set; } = 37.50m;

        /// <summary>
        /// Indicador booleano que determina si el pago de la cita médica ha sido verificado y confirmado.
        /// </summary>
        public bool PagoConfirmado { get; set; } = false;
    }
}
